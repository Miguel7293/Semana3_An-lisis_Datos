1. Objetivo y trazabilidad

Describir la utilización de CPU y evaluar la calidad estructural de una serie temporal antes de modelarla. Se desarrollan las seis actividades y los cuatro entregables de la guía local.

  • Archivo: cpu_utilization_asg_misconfiguration.csv, copia de trabajo incluida junto a este notebook. El original permanece en la carpeta superior.
  • Fuente indicada por la guía: notebook de Kaggle.
  • Referencia primaria consultada el 13/10/2026: README de datos NAB, sección realKnownCause. Describe esta serie como utilización promedio de CPU de un grupo de máquinas AWS.
  • Fecha de descarga y versión exacta: no documentadas en los archivos proporcionados. La fecha de consulta no se presenta como fecha de descarga. Se registra SHA-256 para identificar exactamente el archivo usado.
  • El enlace de Kaggle no expuso sus celdas en la consulta disponible, por lo que no se afirma haber verificado su ruta interna. Se verifican directamente el nombre, las columnas y la ruta local del CSV. No se sustituye la serie.
  • La unidad se interpreta como porcentaje de CPU por el contexto de la guía; el CSV no contiene metadatos de unidad. El control [0, 100] es condicional a esa interpretación.
  • Las fechas carecen de zona explícita. Se adopta UTC para procesarlas de forma consistente, sin afirmar que la fuente haya confirmado UTC. No se convierten a hora peruana.

2. Modelo de datos y alcance

Una fila es una medición del promedio de CPU del grupo en un instante, no un servidor distinto ni un evento individual. La unidad de observación y la unidad de análisis coinciden en esa medición. El recurso observado es el grupo y la unidad temporal se determina mediante las diferencias entre marcas consecutivas.

La población objetivo posible son todas las mediciones de CPU de ese grupo durante el período operativo de interés. Los datos observados son únicamente los registros del archivo. Son una cobertura temporal acotada, no una muestra aleatoria de servidores. Aun con cobertura interna completa, no puede generalizarse a toda AWS ni a todos los servidores de una organización.

Es una serie temporal univariada: una métrica numérica ordenada en el tiempo. Para un estudio transversal se necesitarían identificadores de varios servidores, la misma métrica y períodos comparables. El promedio del grupo podría ocultar diferencias entre máquinas.

4. Auditoría de calidad y regularidad

Los porcentajes usan denominadores explícitos: filas, transiciones entre fechas o puntos esperados de la malla. Los controles pueden solaparse; no se suman como si fueran registros distintos. Duplicados cuenta repeticiones posteriores a la primera aparición.

La frecuencia modal describe lo observado, no acredita por sí sola ausencia de huecos. Por eso se construye además una malla desde el primer hasta el último instante, ambos incluidos, y se compara con las fechas únicas.

5. Decisiones reproducibles

Se conservan los registros válidos y los extremos, incluidos los valores de 100. Un pico plausible no es automáticamente un error. No se imputan valores, no se recortan extremos y no se eliminan duplicados automáticamente.

Para esta ejecución se exige que no existan incidencias estructurales antes de agregar: si cambia el archivo y falla un control, se detiene el análisis para investigar. Una fecha inválida requeriría cotejo con la fuente; un duplicado necesitaría determinar si es retransmisión o una medición distinta; un hueco exigiría revisar el monitoreo antes de imputar. Las transformaciones efectivas son conversión de tipos y ordenamiento estable. Las marcas exploratorias de carga alta no alteran los datos ni equivalen a etiquetas oficiales de anomalía.

6. Resúmenes por hora y día y cobertura

count cuenta valores numéricos disponibles. Media y mediana resumen el nivel, mínimo y máximo conservan extremos, y std es la desviación estándar muestral (ddof=1). Los intervalos se cierran a la izquierda y se etiquetan por su inicio.

Se esperan 12 mediciones en una hora completa y 288 en un día completo, dada una frecuencia de cinco minutos. Cobertura interna compara con los puntos esperados dentro de los límites del archivo. Cobertura del intervalo completo compara con toda la hora o día calendario. Los extremos del archivo pueden ser parciales sin indicar fallas internas.

Ver código reproducible
def resumir(frecuencia, duracion):
    tabla = serie.resample(frecuencia, closed='left', label='left').agg(['count','mean','median','min','max','std'])
    esperados = pd.Series(1, index=malla).resample(frecuencia).sum()
    tabla['esperados_en_ventana'] = esperados.astype(int)
    tabla['esperados_intervalo_completo'] = int(pd.Timedelta(duracion)/paso)
    tabla['cobertura_interna_pct'] = 100*tabla['count']/tabla['esperados_en_ventana']
    tabla['cobertura_intervalo_pct'] = 100*tabla['count']/tabla['esperados_intervalo_completo']
    tabla['intervalo_parcial'] = tabla.esperados_en_ventana < tabla.esperados_intervalo_completo
    return tabla
